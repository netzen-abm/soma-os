# SOMA — Research Capability Authorization Integration Audit v1\n\n## Status\n\nImplemented audit baseline after research-source contract convergence.\n\n## Finding\n\nThe existing registry already contains the canonical `evidence.research` capability. Its adapter boundary is `research-providers`, and its policy set includes privacy, safety and provenance.\n\nNo provider-specific authorization capability is required for the initial source layer. OpenAlex, PubMed, Unpaywall, Semantic Scholar and DOAJ remain provider adapters behind the shared research capability rather than becoming separate product capabilities.\n\n## Canonical execution path\n\n```text\nPrincipal / Identity\n        ↓\nCanonical Authorization + Policy Decision Boundary\n        ↓\nevidence.research\n        ↓\nGoverned Capability Operation\n        ↓\nResearch Source Adapter Contract\n        ↓\nProvider Adapter\n        ↓\nExternal Provider\n        ↓\nNormalized ResearchRecord\n        ↓\nEvidence Research Core\n```\n\n## Authorization requirements\n\nA research-source operation must not invoke a provider adapter before the governing operation has established:\n\n- verified principal/identity context;\n- applicable subject/scope where required;\n- `evidence.research` capability;\n- concrete resource and action;\n- declared research purpose;\n- policy decision;\n- bounded operation/permission state where applicable.\n\nProvider credentials are infrastructure credentials and never substitute for SOMA authorization.\n\n## Privacy requirement\n\nProtected SOMA health information must not be forwarded to research providers merely because `evidence.research` is allowed. The operation must minimize/de-identify the research query before provider transmission.\n\n## Provider isolation\n\nProvider failure remains inside the research adapter/orchestration boundary. It must not weaken authorization, change policy semantics, or be converted into evidence absence.\n\n## Decision\n\nKeep one canonical registry capability, `evidence.research`, for the current research-source layer.\n\nDo not add:\n\n- one capability per provider;\n- a provider-specific policy engine;\n- provider-specific authorization logic;\n- a second operation envelope;\n- provider credentials as user authorization.\n\nProvider-specific capabilities may be introduced later only if a distinct policy/security boundary is demonstrated.\n\n## Next bounded implementation\n\nThe next provider integration is Unpaywall as an access-location resolver behind `evidence.research`. It must preserve work identity, access-location provenance and provider failure semantics and must not assess evidence quality.
